# Sayra Core

Ядро модульного ассистента для Windows 10/11 x64 на C++20. Поддерживает локальные модели Ollama, облачный OpenAI-compatible API, выбор модели по задаче, работу с проектными файлами и историю бесед.

**Проверка от 18 октября 2026:** автономные тесты Debug x64 — **28/28 PASS**, код завершения `0`. Интеграция CLI с Ollama и облачным API требует отдельной проверки. Подробнее: [состояние реализации](docs/IMPLEMENTATION_STATUS.md).

## Состав проекта

- `sayra-core` — библиотека ядра.
- `sayra-cli` — консольное приложение.
- `sayra-core-tests` — автономные тесты с подменными провайдерами.
- `sayra-model-tests` — отдельное приложение диагностики моделей из `Sayra.cpp`.

Исходники расположены в `include/`, `src/`, `apps/` и `tests/`. Конфигурация зависимостей находится в `vcpkg.json`.

## Запуск в Visual Studio 2026

Требуются MSVC v145, Windows SDK, компоненты разработки классических приложений на C++, Git и vcpkg. Библиотеки: libcurl с Windows TLS, nlohmann/json и SQLite3.

1. Откройте `Sayra.slnx`.
2. Выберите **Debug | x64**.
3. Назначьте `sayra-cli` запускаемым проектом.
4. При необходимости скопируйте `config/sayra.example.json` в `sayra.json` в корне репозитория. Без файла конфигурации действует локальный режим.
5. Нажмите **Локальный отладчик Windows** (F5). При первой сборке vcpkg восстановит зависимости.

Рабочий каталог отладчика — корень репозитория. Результаты сборки находятся в `out/vs/x64/Debug` или `Release`. Для запуска автономных тестов назначьте запускаемым проектом `sayra-core-tests`.

Если `tools/vcpkg` отсутствует:

```powershell
git clone https://github.com/microsoft/vcpkg.git tools/vcpkg
```

## Сборка через CMake

В Developer PowerShell for VS 2026 из корня репозитория:

```powershell
.\tools\vcpkg\bootstrap-vcpkg.bat -disableMetrics
cmake --preset vs2026-x64
cmake --build --preset debug
.\build\core\Debug\sayra-cli.exe .\sayra.json
ctest --preset debug
```

В Visual Studio также доступен режим «Открыть папку» с preset `vs2026-x64`. Настройки native-решения находятся в `build-support/`, конфигурация CMake — в `CMakeLists.txt`.

## Локальные модели

Ollama должен быть запущен на адресе, указанном в конфигурации; по умолчанию это `http://127.0.0.1:11434`. Доступные модели обнаруживаются через API. Для диалога нужна хотя бы одна chat-модель, для `/embed-test` — BGE-M3. Sayra не загружает веса автоматически.

```powershell
ollama pull bge-m3
```

Просмотр моделей и первый запрос:

```text
/models
Привет
Создай класс на C++20 для управления задачами
/why-model
```

Специализации задаются в `models` файла `sayra.json`. Имя должно совпадать с выводом `/models`:

```json
{"name":"installed-model:tag","provider":"ollama","chat":true,
 "roles":["coding"],"context":8192,"priority":10}
```

Для демонстрации переключения нужны две модели с разными профилями. При отсутствии специализированной модели выбирается доступный общий кандидат. Изменения конфигурации применяются после перезапуска. Подробнее: [маршрутизация](docs/MODEL_ROUTING.md).

## Команды CLI

| Команды | Назначение |
|---|---|
| `/help`, `/status`, `/doctor` | Справка и диагностика |
| `/models`, `/model auto`, `/model <name>` | Обнаружение и выбор модели |
| `/mode local`, `/mode cloud`, `/mode hybrid`, `/mode auto` | Режим маршрутизации |
| `/why-model` | Кандидаты и причины последнего выбора |
| `/project list`, `/project add <path>`, `/project use <id>`, `/project info` | Управление проектами |
| `/new`, `/history`, `/history list`, `/history load <id>`, `/history delete <id>` | Беседы и история |
| `/embed-test`, `/live-demo` | Диагностические сценарии |
| `/cancel`, `/exit` | Отмена и выход |

Обычный текст отправляется как запрос. Генерация выполняется в `std::jthread`; во время неё доступны `/cancel` и `/exit`. Диагностика при старте и обновление списка моделей выполняются синхронно с таймаутом. Поддерживаются русский текст и UTF-8.

## Работа с проектом

```text
/project add "C:\Projects\Sayra"
/project info
Объясни файл src/routing.cpp из выбранного проекта
/history
```

Регистрация каталога разрешает чтение допустимых текстовых файлов в его пределах. При переключении проекта создаётся отдельная беседа. Явно указанный относительный путь читается и без native tool calling; для остальных запросов доступны список файлов и инструменты поиска. Объём файла и контекста ограничен настройками.

## Облачный API

Облако по умолчанию выключено. Для подключения задайте:

- `cloud.enabled: true` и HTTPS `base_url` с префиксом API, например `/v1`.
- Имя переменной окружения с ключом в `cloud.key_env`; по умолчанию `SAYRA_CLOUD_API_KEY`.
- Профиль обнаруженной облачной модели: `provider: "cloud"`, `chat: true`, возможности, роли и `cost_per_1k_tokens`.
- Допустимый потолок цены в `cloud.max_cost_per_1k_tokens`.

После настройки перезапустите CLI и выберите `/mode cloud`. API должен поддерживать `/models` и `/chat/completions`. Содержимое проекта и транскрипция требуют отдельных разрешений `allow_project_data` и `allow_transcripts`. Ключи в JSON не сохраняются. Подробнее: [провайдеры API](docs/API_PROVIDERS.md).

## Диагностические сценарии

`/embed-test` получает векторы для шести наборов предложений, проверяет размерность BGE-M3 1024, конечность и ненулевость значений. Для каждого набора выводятся cosine AB/AC, разница и PASS/FAIL. Значения вычисляются из ответа Ollama.

`/live-demo` подаёт предварительный и окончательный текстовый сегмент о `std::mutex`. В LLM поступает только окончательная транскрипция; ответ передаётся через события и карточку. Аудиозахват в этом сценарии отсутствует.

Без подключённого Research-сервиса запрос актуальной информации возвращает сообщение о необходимости веб-поиска. Проверенные источники из ответа LLM не создаются.
