# Публикация открытого репозитория

В Git должны входить исходники include/src/apps/tests, docs, безопасный config/sayra.example.json, CMakeLists.txt/CMakePresets.json, vcpkg.json, build-support/Sayra.Common.props, .slnx/.vcxproj/.filters, .clang-format и .gitignore.

Не публикуйте sayra.json, конфиги *.local.json/*.private.json, .env, реальные ключи/сертификаты, историю SQLite, проекты пользователя, транскрипции, записи аудио, логи/дампы, персональные IDE-настройки *.user/.vs, каталоги сборки, скачанный vcpkg и модели. .gitignore содержит правила для этих стандартных имён. Если задаёте произвольный data_dir или имя рабочего конфига, добавьте соответствующий путь в локальный .git/info/exclude либо согласованный .gitignore до git add.

Пример конфигурации остаётся публичным и должен содержать только безопасные настройки/имена переменных окружения. Настоящий API key передаётся через окружение, никогда не через пример или исходник. Не записывайте ключи даже в файлы с именем example.

.gitignore защищает по именам, а не анализирует содержимое. Он не очищает уже отслеживаемые файлы и историю коммитов. Перед коммитом просмотрите git status и staged diff. При утечке ключа нужно отозвать его у провайдера; удаление файла последующим коммитом не делает ключ безопасным.

Проверка распространённых форматов токенов не заменяет просмотр staged diff перед публикацией. Для уже отслеживаемых приватных файлов требуется отдельное удаление из индекса и, при необходимости, очистка истории.

Правила игнорирования распространяются на данные последующих сборок и запусков.
