# Маршрутизация моделей

Registry использует /api/tags, /api/ps и /api/show. Специализация не угадывается по слову coder. Профиль — назначенные человеком роли и оценки; capabilities — сведения сервера. Embedding никогда не является chat-кандидатом.

Classifier рассматривает совместно текстовые признаки, наличие проекта, имена файлов, историю коротких уточнений, актуальность, realtime и чувствительность. Возвращает primary/secondary, needs_tools/web, fast, private_data, required_context и объяснение. Это эвристика, не обученная оценка качества. Если ambiguous и настроена реально доступная classifier_model, допускается отдельное ограниченное LLM-уточнение. Оно не повышает права, не применяется к realtime.

До scoring отбрасываются недоступные, embedding/non-chat, запрещённые режимом и приватностью кандидаты, а также известный недостаточный context. Cloud требует enabled/permission, HTTPS/ключ/успешное обнаружение, известную настроенную цену и соответствие потолку. Для проекта и транскрипции нужны отдельные согласия. Sensitive-флаг запрещает cloud независимо от приоритета. Manual — точное имя, неизвестная модель даёт ошибку.

Оценка: profile.priority + 30 за настроенную целевую роль + 10 за local + 4 за loaded + ограниченная quality + speed для fast + 5 за native tools, если они нужны. Все оценки quality/speed пользовательские, не измеренные ядром. Стоимость — фильтр; это потолок заявленной цены на 1000 токенов, а не расчёт фактического счёта провайдера. Общую стоимость ограничивайте также средствами аккаунта API.

Auto и Hybrid сейчас используют общий score: локальное предпочтение, но без обязательной двойной генерации или отправки проекта в облако. LocalOnly/CloudOnly жёстко ограничивают провайдера. /model задаёт forced_model независимо от режима; /model auto снимает фиксацию.

Причины, кандидаты, исключения, fallback доступны через /why-model. Runtime fallback пробует следующего допустимого кандидата только до видимого модельного текста, не при отмене и не при принудительной модели. Он учитывается в общем agent iteration budget и повторно проверяет privacy. После частичного ответа повтор не выполняется, чтобы не смешать два ответа.

Generation context ограничивается конфигурацией и известным контекстом модели. Для оценки используется консервативный байтовый бюджет с резервом output tokens, а не точный tokenizer конкретной модели. При переполнении удаляется только старая история до текущего user prompt; tool exchanges не разрываются. Если не помещается текущий запрос/данные — понятная ошибка вместо незаметной отправки всего проекта.

Пример профиля (замените имя на реальное из /models):

```json
{"name":"installed-model:tag","provider":"ollama","chat":true,"tools":true,
 "roles":["coding","reasoning"],"context":8192,"priority":10,"quality":7,"speed":4}
```

`tools:true` задавайте лишь при реальной поддержке. Новая конфигурация применяется после перезапуска приложения; /models обновляет обнаружение в рамках загруженного конфига.
